# 朗读女 Neo · Windows 一键自检 · 结果解读

这个文件是给运行自检的你看的。看完这份说明，报告文件 (`win-selfcheck-<时间戳>.txt`) 里出现的每个数字是什么意思、什么算正常、什么算异常，就都清楚了。

---

## 一、怎么运行

**双击 `app\scripts\win-selfcheck.cmd`，就这一下。**

- 如果本地语音引擎（NVSA）还没注册，会弹一次"用户账户控制"(UAC)窗口，点**【是】**即可（整个流程只需要这一次授权；已经注册过则不会弹任何窗口）。
- 脚本会自动跑完 7 个步骤，中途需要你配合的只有一步：第 6 步会提示你**拔网线 / 开飞行模式**，然后按回车继续。
- 全部跑完后，**结果文件夹会自动打开**，里面的 `win-selfcheck-<时间戳>.txt` 就是本次报告。
- 把这个 txt 文件（或者整个 results 文件夹）发回给编排者即可。不需要懂技术，也不需要额外操作。
- 自检结束后，黑色窗口最后一行会给出总体结论：**全部通过 / 通过但有警告 / 未通过**——与报告末尾的"总体结论"一致。
- 每次运行都会生成一个新文件（文件名带时间戳），历史报告不会丢；发最新那个就行。

> 想卸载本地语音包：在 `scripts\register-nvsa.cmd` 上右键 → 以管理员身份运行，或命令行执行 `register-nvsa.cmd -Unregister`。

---

## 二、报告结构

报告按 7 个步骤顺序记录，每步结尾有一行 `>> 步骤 N 结论: PASS / WARN / FAIL`，最后有汇总表和总体结论。

| 步骤 | 内容 | 看什么 |
|---|---|---|
| 1 | 环境信息 | Windows / PowerShell / Node 版本；NVSA 是否已有注册痕迹 |
| 2 | 幂等注册 | 调用 `register-nvsa.ps1` 的结果和退出码（已注册则跳过） |
| 3 | 注册核对 | 注册表三项值 + 系统里有哪些 SAPI 语音 |
| 4 | 引擎探测 | 现在实际用哪个引擎、本地是否可用、有没有发生降级 |
| 5 | 延迟实测 | 本地合成 5 次的耗时（**重点**）+ 在线 Edge 对照 |
| 6 | 断网复测 | 拔网线后本地语音是否依然正常 |
| 7 | 汇总 | 每步 PASS/WARN/FAIL + 总体结论 |

---

## 三、关键数字的含义

### 延迟（步骤 5，最重要的部分）

| 字段 | 含义 |
|---|---|
| `elapsedMs` | **一次合成的端到端耗时**（毫秒）。这是热键按下到出声音的等待时间，对低视力用户是可用性红线 |
| `durationMs` | 合成出来的**音频时长**（毫秒），不是等待时间 |
| 第 1 次 | 含预热（引擎首次加载），**偏大是正常的**，统计时已自动排除 |
| 第 2–5 次 | 真实水平。报告给出平均值/最小值/最大值 |

判定标准：**本地平均 ≤ 300ms = PASS**（红线）；300–800ms = WARN（能用但偏慢）；> 800ms = FAIL。
合成音频样本保存在 `app\dist\probe\`，可以直接播放试听。

### 引擎（步骤 4）

| 字段 | 含义 |
|---|---|
| `active` | 当前实际发声的引擎。**`sapi` = 本地离线语音（NVSA），这是期望值**；`edge` = 在线语音（兜底） |
| `local.available` | 本地 NVSA 是否可用 |
| `reason` / `message` | 本地不可用时的原因（如 `VOICE_NOT_REGISTERED` = 晓晓/云希未注册） |
| `degraded` | 是否发生了降级（没用上首选引擎） |
| `chain` | 引擎链路顺序：`sapi -> espeak -> edge`。注意：`espeak` 是沙箱/CI 专用验证引擎，Windows 上**一定不可用、会被自动跳过**——在 chain 里看到它是正常的，不影响本地语音 |

### 注册表三项（步骤 3）

| 值 | 期望 | 含义 |
|---|---|---|
| `NarratorVoicePath` | 指向一个**存在的目录** | NVSA 去哪里找语音文件 |
| `NoEdgeVoices` | `1` | 不在本地列表里暴露在线 Edge 语音（保持纯离线） |
| `NoAzureVoices` | `1` | 同上，关闭 Azure 语音 |

### 退出码（步骤 2）

`0` = 成功（含"已注册，跳过"）；`2` = 下载失败；`3` = 管理员授权被拒；`4` = 解压/注册失败；`5` = 注册了但枚举不到语音。

---

## 四、什么算正常 / 异常

**正常（PASS）**：所有步骤 PASS，本地平均延迟 ≤ 300ms，断网后本地合成依然 ok。把报告发回去就行。

**基本正常（WARN）**：功能可用但有瑕疵，例如：当前走在线 Edge 兜底（本地没生效）、延迟 300–800ms、断网测试时网络似乎没真正断开。**也请把报告发回**，附上的数字就是编排者调代码的依据。

**异常（FAIL）**：本地引擎不可用 / 本地合成失败 / 注册失败 / 延迟 > 800ms。对照下表先自助排查，仍不行就把报告发回。

## 五、常见问题自助对照

| 报告里的现象 | 原因与处理 |
|---|---|
| 步骤 2 退出码 `2` | 组件下载失败（约 140MB）。检查网络/防火墙后重新双击运行 |
| 步骤 2 退出码 `3` | UAC 弹窗点了"否"。重新双击运行，点"是" |
| 步骤 2 退出码 `5` | 注册流程走完但枚举不到语音。**重启电脑**后重新双击运行；仍失败可能是安全软件拦截了 DLL 注册 |
| 步骤 4 `active=edge` | 本地语音没生效。看同段的 `reason`：`VOICE_NOT_REGISTERED` = 没注册；`NO_POWERSHELL`/`HOST_START_FAILED` = PowerShell 通道起不来 |
| 步骤 5 平均 > 300ms | 如实记录数字即可。机械硬盘、安全软件实时扫描、老旧电脑都可能拖慢首次加载 |
| 步骤 6 "网络可能没有真正断开" | 拔网线/飞行模式没生效（例如仍连着手机热点）。重新断网后单独重跑一次自检 |
| 步骤 1 `Node: 未找到` | 需要 Node.js。安装 Node.js LTS 后重跑；或保持交接包 `app\node_modules` 完整（脚本会尝试用其中的 Electron 内置 Node） |
| 双击后闪退 | 右键 `win-selfcheck.cmd` 用记事本打开，确认没有被安全软件隔离 |

## 六、两个常见误解（澄清）

1. **"本地语音效果垃圾"是误记。** NVSA 跑的是与在线 Edge **完全相同**的微软神经语音（`zh-CN-XiaoxiaoNeural` / `YunxiNeural`），音质一致，没有任何退化。历史上"效果差"的评价属于另一个引擎（Kokoro），被误记到了 NVSA 名下。
2. **第 1 次延迟偏高是正常的**（含引擎预热与模型加载），这正是统计从第 2 次开始的原因；产品内已有后台预热机制，实际热键体验以第 2–5 次的数字为准。

## 七、交付说明（重要）

- 本自检包交付时**只在 Linux 沙箱中做了静态校验（语法 + 接口核对），未在 Windows 真机实跑**；报告中的所有数字都来自你的电脑实跑，是真实结果。
- 自检脚本**只读不改**：除注册语音引擎（步骤 2，幂等）外，不会改动系统设置；不收集任何个人信息，报告只在你自己电脑上生成。
- 脚本清单：`app\scripts\win-selfcheck.cmd`（双击入口）、`app\scripts\win-selfcheck.ps1`（自检逻辑）、`app\scripts\register-nvsa.ps1`（被调用的注册脚本）、`app\scripts\probe-engine.js`（被调用的探测脚本）。
