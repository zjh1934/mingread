> 适用版本：v2.4.0 ｜ Electron 32.3.3 ｜ electron-builder 25.1.8 ｜ 目标平台 win32-x64
> 配置文件：`app/electron-builder.yml`（唯一真源，`package.json` 里没有 `build` 字段）

## 1. 怎么打

```bash
cd app

# 渲染层必须先构建（打包只收 dist/renderer，不会替你跑 vite）
node node_modules/vite/bin/vite.js build

# 方式 A：安装包 + 免安装 zip（= npm run pack）
node node_modules/electron-builder/out/cli/cli.js --win nsis zip

# 方式 B：只出免安装目录，最快，用于验证配置 / 跑冒烟
node node_modules/electron-builder/out/cli/cli.js --win --dir
```

`npm run pack` / `pack:dir` / `pack:zip` 三个脚本已经加好，等价于上面三条命令。

首次打包需要下载 Electron 运行时（113MB）和 NSIS 工具链。国内网络先设镜像：

```bash
export ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
export ELECTRON_BUILDER_BINARIES_MIRROR="https://npmmirror.com/mirrors/electron-builder-binaries/"
```

```powershell
$env:ELECTRON_MIRROR = "https://npmmirror.com/mirrors/electron/"
$env:ELECTRON_BUILDER_BINARIES_MIRROR = "https://npmmirror.com/mirrors/electron-builder-binaries/"
```

实测：镜像下 Electron 113MB 约 4s、nsis 1.3MB 约 3s，完整 `nsis zip` 打包约 1 分 40 秒。

## 3. 配置要点（`app/electron-builder.yml`）

| 配置 | 值 | 原因 |
|---|---|---|
| `directories.output` | `release` | 与 `dist/`（渲染产物）分离 |
| `files` | 白名单：`dist/renderer/**`、`src/main/**`、`src/preload/**`、`src/shared/**`、`resources/**`、`package.json`、`LICENSE`、`README.md`、`THIRD-PARTY-NOTICES.md` | 不允许整目录进包；`src/renderer`（源码）、`docs`、`scripts`、`results`、`public`、`dist/probe` 全部排除 |
| `asar` | `true` | 源码合并成 `app.asar`（本次 1.81 MB） |
| `asarUnpack` | `node_modules/koffi/**`、`node_modules/@koromix/**` | 原生模块不能进 asar，见 3.1 |
| `npmRebuild` | `false` | koffi 是 N-API 预编译二进制，跨 ABI，不需要 node-gyp（本机也没有 VS 构建链） |
| `extraResources` | `resources/icon.png → resources/icon.png` | 主进程窗口图标优先读 `process.resourcesPath/icon.png` |
| `win.icon` | `resources/icon.ico` | 已含 16/32/48/64/128/256 六档，满足 Windows 256×256 要求 |
| `win.target` | `nsis` + `zip`，`arch: [x64]` | 安装包 + 免安装双产物 |
| `nsis.oneClick` | `false` | 保留向导，可选安装目录（`allowToChangeInstallationDirectory: true`） |
| `nsis.language` | `2052` | 简体中文向导 |
| `nsis.deleteAppDataOnUninstall` | `false` | 卸载不删用户设置和已下载的 voice-pack（重装不用重下 142MB） |

### 3.1 koffi 为什么必须 `asarUnpack`（最容易踩的坑）

koffi 是 F1 旁路捕获的底层依赖（`src/main/platform/keyboardHook.js` 用 WH_KEYBOARD_LL 低级键盘钩子，
当别的程序独占 F1 时靠它照样能收到按键）。它是原生模块，`require('koffi')` 最终要 `dlopen` 一个 `.node` 文件——
**asar 是虚拟归档，`dlopen` 读不了**，一旦进 asar 就会抛 `Cannot find the native Koffi module`，
F1 只剩「被占用，朗读暂不可用」一条路。

koffi 3.3.3 的二进制**不在 koffi 包里**，而在可选依赖里：

```
node_modules/@koromix/koffi-win32-x64/win32_x64/koffi.node     ← 真正的原生二进制（1.0 MB）
node_modules/koffi/index.cjs → ./src/koffi/index.cjs           ← 加载器，按顺序尝试
     ① ../../../@koromix/koffi-win32-x64
     ② <resourcesPath>/koffi/win32_x64/koffi.node
     ③ <koffi>/../../build/koffi/win32_x64/koffi.node
```

所以两个包都要解包：`asarUnpack` 里 `node_modules/koffi/**` 与 `node_modules/@koromix/**` 缺一不可。
打包后应能在 `release/win-unpacked/resources/app.asar.unpacked/node_modules/` 下看到：

```
koffi/index.cjs
koffi/src/koffi/index.cjs
koffi/src/koffi/src/static.cjs          ← 运行时代码，不能排除
koffi/src/koffi/src/trampolines.cjs
@koromix/koffi-win32-x64/win32_x64/koffi.node
```

> 踩坑记录：一开始为了瘦身写了 `!node_modules/koffi/src/koffi/src/**`，结果把 **运行时的**
> `static.cjs` 一起排掉了，打包后报 `Cannot find module './src/static.cjs'`，钩子直接降级。
> 该目录里 `.cc/.hh` 是编译期源码，但 `.cjs` 是运行时必需——**不要整目录排除**。当前配置只排除
> `koffi/doc`、`koffi/vendor`、`*.d.ts`。

### 3.2 语音包为什么不进安装包

NVSA 语音资源（约 142 MB：引擎 DLL + 晓晓/云希语音包）由 `src/main/voicePackSources.js` **运行时下载**，
落到 `%LOCALAPPDATA%\langdu-nv\voice-pack\`。`files` 是白名单且不含任何 `voice-pack` 路径，
因此安装包只含程序本体。验证方式：`app.asar` 仅 1.81 MB、325 个条目，搜不到 `voice-pack` / `.onnx` / 语音数据文件。

## 4. 图标

- `resources/icon.ico`：6 档尺寸（16/32/48/64/128/256），已满足 electron-builder 对 Windows 图标的要求，**不需要额外生成**。
- `resources/icon.png`：256×256，作为窗口/托盘图标经 `extraResources` 放到 `resources/icon.png`。
- 换图标只替换这两个文件，PNG 尺寸不得小于 256×256；ICO 用 `scripts/make-icon.py`（既有脚本）或任意工具从同一张 PNG 生成，保持六档。
- 本项目**没有**引入 sharp 等图像依赖——现有 ICO 已合规，无需转换。

## 5. 下次改版本号，只改两处

1. `app/package.json` 的 `"version"` —— **唯一真源**。NSIS 安装包显示版本、`${version}` 产物文件名、`app.getVersion()` 全部跟随它。
2. `app/package-lock.json` 顶部的 `"version"`（两处：根 `version` 与 `packages[""].version`）——`npm install` 会自动回写；改完 package.json 后跑一次 `npm install --package-lock-only` 最稳。

不要改：`name`（`langdu-nv-neo`，影响 NSIS 卸载注册表键）、`main`、`dependencies`、`productName`。

## 6. 打包后自测（本次实际跑过的四项）

在 `app/release/win-unpacked/` 下执行。**先清 `ELECTRON_RUN_AS_NODE`**（本机该变量为 1 时 electron.exe 会当 node 跑，窗口起不来）。

```bash
unset ELECTRON_RUN_AS_NODE
export ELECTRON_ENABLE_LOGGING=1
```

**① 能启动 + ② 主界面渲染**：`--capture=<png>` 模式加载真实 `dist/renderer/index.html`，约 3.5s 后截图并退出。

```bash
"release/win-unpacked/朗读女 Neo.exe" "--capture=C:/Temp/shot.png"
```

**③ F1 钩子（koffi）在产物里生效**：先让别的进程占住 F1，再启动产物。

```bash
node_modules/electron/dist/electron.exe scripts/probe-hotkey-conflict-holder.js F1   # 占住 F1
"release/win-unpacked/朗读女 Neo.exe"
```

日志应出现（本次实测原文）：

```
[zoom] 输入后端: backend=koffi trigger=koffi zoomHotkeyOk=false
[hotkey] register accelerator=F1 ok=false
[hotkey] low-level hook took over accelerator=F1 vk=112
```

`backend=koffi` 与 `low-level hook took over` 两行同时出现，才说明 koffi 原生库真的从
`app.asar.unpacked` 加载成功、`SetWindowsHookExW` 安装成功。

进一步证明「钩子确实收到了按键」（用 koffi 注入一次真实 F1，走完整系统输入链）：

```
[hotkey] press cue ok=true tookMs=30 at=1792844542208
[hotkey] fired -> source=none code=NO_SELECTION len=0 tookMs=1231 totalMs=1259
[hotkey] press cue ok=true tookMs=2  at=1792844545251
[hotkey] fired -> source=none code=NO_SELECTION len=0 tookMs=1206 totalMs=1206
```

（`NO_SELECTION` 是因为当时没有选中任何文字，属预期；关键是 `press cue` 与 `fired` 都被触发。）

**④ 本地语音可用**：加 `--remote-debugging-port=9234` 启动，用 CDP 读渲染进程的真实状态：

```js
window.langdu.voice.getStatus().then(s => s.engine)
// { id: "sapi", label: "本地离线语音（NVSA）", online: false, ready: true, voiceCount: 2, lastError: null }
window.langdu.voiceDeploy.getState().then(s => s.state)   // "READY"
```

本次实测同时确认：主窗口标题 `朗读女 Neo · 选中文字按 F1 即读`、`h1=朗读女 Neo`、
按钮「本地语音已就绪（不联网、延迟最低），点击重新检测」、加载的 bundle 为
`index-z7fUur9r.js`（与打包时刻的 `dist/renderer` 一致）。

证据留档在 `app/release/_verify/`：`packaged-ui.png`、`最终产物-运行日志.log`。

## 7. 常见失败与排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `downloading ... electron-v32.3.3-win32-x64.zip` 卡住/超时 | 直连 GitHub 慢 | 设 `ELECTRON_MIRROR`（见 §1）；本机 `node_modules/electron/dist` 已就位时也可直接复用 |
| `nsis-3.0.4.1.7z` / `winCodeSign` 下载失败 | electron-builder 二进制源被墙 | 设 `ELECTRON_BUILDER_BINARIES_MIRROR` |
| 启动即崩、日志 `Cannot find the native Koffi module` | `asarUnpack` 没覆盖 `@koromix/**` | 检查 `resources/app.asar.unpacked/node_modules/@koromix/koffi-win32-x64/win32_x64/koffi.node` |
| 日志 `Cannot find module './src/static.cjs'` | 误把 `koffi/src/koffi/src/**` 排除 | 删掉该排除项，重新打包 |
| 报 `icon.ico must be at least 256x256` | 图标尺寸不足或 ICO 只有小尺寸 | 用 256×256 PNG 重新生成六档 ICO（`scripts/make-icon.py`） |
| 安装包能装但打开白屏 | `dist/renderer` 没构建 / 没进包 | 先 `vite build`；用 `--capture` 截图确认；`asar list` 查 `dist/renderer/index.html` |
| 双击没反应、也没有窗口 | 已有实例在跑（单实例锁）或 `ELECTRON_RUN_AS_NODE=1` | 结束残留进程；`unset ELECTRON_RUN_AS_NODE` |
| 杀软/Defender 报毒或 SmartScreen 拦截 | 未签名的 NSIS 自解压包常见误报 | 正式分发建议买代码签名证书；过渡期可在发布页说明并提供 SHA-256；向厂商提交误报 |
| 打包时提示 `dependencies rebuild` | 有人把 `npmRebuild` 改回 true | 保持 `false`：koffi 是 N-API 预编译，不需要也不应该重建 |

## 8. 已知限制

- **未做代码签名**：安装包与 exe 均无签名，SmartScreen 会提示"未知发布者"。
- `app/release/` **没有**写进 `.gitignore`（本次未改该文件），提交前注意别把 77MB/105MB 的产物塞进仓库。
- 安装包内的渲染层是**打包那一刻**的 `dist/renderer` 快照。本次产物对应 `dist@20:18:18`（`index-z7fUur9r.js`）；
  打包完成后并行开发的 UI 仍在重建 `dist`（20:22:55 → `index-C6a5xbZe.js`、20:24:20 → `index-CdjOamGL.js`）。
  **渲染层冻结后必须再跑一次 `npm run pack`**，否则安装包里是旧 UI。判断方法：`asar list` 或解压后看
  `resources/app.asar` 里 `dist/renderer/assets/index-*.js` 的文件名是否等于当时 `dist` 里的那个。
- NSIS 安装流程只做了产物完整性校验，未做"静默安装 → 启动 → 卸载"全链路回归；发版前建议在干净虚拟机跑一遍。
- 语音包仍需用户首次运行时下载（约 142MB），安装包本身不含语音数据（这是刻意设计，避免 700MB 巨包）。

## 已知坑（2026-10-24 本机实测）

### 1. 第二次打包报 `app.asar ... being used by another process`

现象：首次打包成功，紧接着重打（`--win nsis zip`）失败，日志里是：

```
⨯ remove ...\release\win-unpacked\resources\app.asar:
  The process cannot access the file because it is being used by another process.
```

原因：`app.asar` 句柄还没释放（杀软扫描 / 上一轮产物进程刚退出 / Windows 文件锁）。

两个解法（按成本排序）：
1. **换输出目录**（最省事，已验证可行）：
   ```bash
   node node_modules/electron-builder/out/cli/cli.js --win nsis zip -c.directories.output=release2
   ```
2. 结束占用进程后重试（`Get-Process | Where-Object { $_.Path -like "*win-unpacked*" } | Stop-Process -Force`），
   或注销/重启资源管理器。

### 2. QA 截图参数在打包产物上会 `bad option`

开发模式 `electron . --capture=xxx` 可用，但**打包后的 exe 不接受** `--capture=...`
（Chromium 命令行会把它当非法开关，尤其是参数里含中文路径时先被转码成乱码）。
要验证打包产物，优先用：
- 运行日志（`app.asar` 外的控制台输出重定向）
- 核对产物内 JS 指纹是否与最新构建一致：
  ```bash
  node -e "const a=require('@electron/asar');console.log(a.listPackage('release/win-unpacked/resources/app.asar').filter(f=>/renderer.assets.index-.*js$/.test(f)))"
  ```

### 3. koffi 的正确打包方式（已配好，别改坏）

`koffi 3.x` 的原生二进制不在 `koffi` 包内，而在可选依赖 `@koromix/koffi-win32-x64`。
`asarUnpack` 必须**同时**解包 `koffi` 与 `@koromix`，否则 `require('koffi')` 抛错，
F1 就只能退回「被占用、无法使用」。验收标志：运行日志出现
`[hotkey] low-level hook took over accelerator=F1 vk=112`。
