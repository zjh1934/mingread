# 代码审计记要（v3.2.2）

审计目标：找出**架构冲突**（循环依赖、职责倒置、状态源打架）与**虚空引用**（调用了不存在的东西、引用了已删除的模块）。

## 一、方法：静态 + 运行时，缺一不可

| 手段 | 脚本 | 能查什么 | 局限 |
|---|---|---|---|
| 静态契约扫描 | `scripts/audit-contract.js` | preload 通道 vs 主进程 handler、bridge 方法 vs preload key、本地 require 断链、顶层循环依赖 | **看不懂动态注册和常量名注册**，误报率高 |
| 运行时验证 | `scripts/tmp_audit_ipc_runtime.js` | 直接读 Electron 内部真实注册表，比对 preload 的 44 个 invoke | 需要跑起来；依赖私有字段 |
| 逻辑层人工审计 | `docs/代码审计-渲染层.md`（27 条） | 状态源冲突、订阅泄漏、闭包旧值、无障碍红线 | 需要人判断 |

**教训（写下来避免下次浪费）**：静态扫描报出的 7 条「IPC 断链」**全是误报**——
`zoomController` 用 `Object.entries(handlers).forEach(([ch, fn]) => ipcMain.handle(ch, fn))` 动态注册，
`a11yFeedback` 用常量 `C.IPC_A11Y_ANNOUNCE` 注册。
运行时验证：**主进程实际注册 47 个 handle，preload 的 44 个 invoke 全部命中，0 断链。**

静态审计已改进：识别动态注册后降级为「待确认」，并从 `shared/constants.js` 提取常量通道值。

## 二、真问题（已修）

| 编号 | 问题 | 危害 | 修法 |
|---|---|---|---|
| **ARC-1** | **真循环依赖**：`settingsStore` 为了拿一个常量对象 `ZOOM_DEFAULTS`，反向 require 了 1100 行的 `zoomController`；而 zoomController → a11yFeedback → ttsBridge → backends → sapiBackend → voiceSources → settingsStore 绕回来 | require 顺序一变，某一方会拿到**未执行完的空 exports**，表现为莫名其妙的 `undefined`。当前恰好顺序对，属于「随时会炸」的隐患 | 把 `ZOOM_DEFAULTS` 下沉到 `src/shared/zoomDefaults.js`（零依赖），两层各自引用。环断开，顶层循环依赖归零 |
| **A-01** | 热键提示音是**假开关**：开关在渲染层、读取在 hotkeyTray，但 `saveSystemSettings` 的白名单里没有 `hotkeyCue` | 界面显示「已开启」→ 实际不响 → 重启又关回去。用户会以为软件坏了 | 白名单 + 设置快照各补一项 |
| **F-03** | 大字号档（1.5x/2.0x）下 `index.css` 给**所有** `.MuiBox-root` 加了 `overflow: visible !important` | 限高+内部滚动的容器（当前句 / 句列表 / 章节 / 关于页）变成「限高+溢出」，文字直接叠到下面的卡片上。**对必须用大字号的核心用户等于看不清** | 给这类容器加 `data-scroll="1"`，CSS 加例外规则保留 `overflow: auto` |
| **E-02** | 暂停听长文时，鼠标停在任意文字上 → 悬停朗读直接 `start()`，**整本书进度和缓存被清空**，且无提示 | 数据丢失。主进程 `isBusy` 只看 `isPlaying`，暂停态拦不住 | 渲染层加判断：有音频但没在播 → 跳过并提示一次 |
| **F-01** | 句列表展开按钮只有约 32px 高 | 低于无障碍 44px 红线，低视力用户点不中 | `minHeight: su(44)` |
| **G-02** | `VoicePicker` 里硬编码 `.slice(0, 2)`，只显示前两个音色 | **「音色源」功能白做**——用户从自建源里装的发音人根本选不到 | 去掉截断，列表限高可滚，多于 2 个时提示「共 N 个，可滚动」 |
