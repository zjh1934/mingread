# 延迟攻坚报告 · v2.4.0

> 2026-10-24｜目标：用户诉求「选中文字按 F1 就读，不要有延迟」
> 结论：**已达成**。端到端从 2169ms 降到 169ms（P95），F1 在被其他程序独占时仍可正常使用。

## 二、三个关键发现

### 1. F1 根本抢不到 —— 不是「重试能解决」的问题

本机 `globalShortcut.register('F1')` 恒返回 `false`：F1 被会话外程序用 `RegisterHotKey` 独占（网吧管理客户端一类）。该 API 是**独占**的，任何重试都不可能成功。

**解法**：用 koffi（MIT）安装 `WH_KEYBOARD_LL` 低级键盘钩子。钩子挂在系统输入分发链最前端，热键被独占也照样收得到。实测 3 次注入 3 次命中。

安全保障：永不吞事件（一律 `CallNextHookEx`）、只比对键码不记录内容、回调只做去重 + `setImmediate` 派发（低级钩子 300ms 超时会被系统静默摘除）。

三层保障：官方 API → 钩子旁路 → 冲突播报 + 5s 重试；官方 API 恢复后立刻卸钩子（避免一次按键读两遍）。

### 2. 在线链路有物理下限，本地才是解

Edge 单次调用下限 ≈ **0.87s TLS 握手 + 0.3s 服务端首包 ≈ 1.2s**。`node-edge-tts` 每次合成新建 WebSocket、`turn.end` 后关闭，TLS 会话不复用（实测 `reused=false`，关证书校验仍 907ms）。保活只能省掉模块加载 + DNS 约 0.24s，摊薄不了握手。

### 3. 系统自带语音被白名单挡住 —— 延迟最大的那笔浪费

`pickSapiVoices` 只认晓晓/云希，系统内置的 `Microsoft Huihui` 被直接丢弃 → 本地引擎判「未注册」→ 被迫走 Edge。

而实测它走常驻通道合成只要 **18~43ms**（预热 547ms），比神经语音还快。

现在把它加成一层兜底：**NVSA 未装/装坏时，本地照样零延迟出声**，且带明确提示（`kind='system'` + `notice`），不静默降级。

## 五、还没做的

1. **F1 + 真实选区的人工听感复测**：链路已通（钩子→抓取→合成→播放），但「在 Word/浏览器里选中一段话按 F1」需要真人按一次确认，我用注入键无法稳定复现选区。
2. **Phase 2 UI 信息架构重构**：交接文档里你最早提的「没有主次、没考虑操作习惯」。
3. **koffi 启用后 zoom 滚轮钩子的行为回归**：装 koffi 让缩放模块也走上了钩子模式（原设计如此，但此前从未真机验证）。
4. **探针清理归档**：`tmp_probe_*` 系列转正或进归档目录。

## 六、怎么自己验一遍

1. 打开应用，确认顶部显示「选中文字按 F1 即读」，音色显示「晓晓」
2. 在浏览器或 Word 里选中一段文字，按 **F1**
3. 应该几乎立刻出声（约 150~200ms），且读完还原你的剪贴板

如果按 F1 没反应，看托盘气泡或语音提示：它会明确说是「F1 被谁独占、已用底层监听接管」还是「没有选中文字」。
